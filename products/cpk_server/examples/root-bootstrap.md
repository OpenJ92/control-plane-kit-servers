# Explicit Docker root bootstrap

This is the external acquisition exception for a new root CPK installation.
`DockerCpkInstallation` remains the desired-definition owner. The driver compiles
that value, acquires its three products with ordinary Docker, then initializes
the root through authenticated public HTTP. It does not invent Operations run
identities. The newly created workspace has its normal initial graph; acquisition
does not claim that CPK deployed or tracks itself.

Docker must already be running on the user-owned host. The Docker-enabled CPK
server is a trusted host administrator. Its socket is not a tenant boundary.
Only loopback port publication is supported here. Supply an existing HTTPS
endpoint as intent; this bootstrap does not provision DNS, tunnels or ingress.

Build the external driver on the accepted CPK image, then retain its exact local
image ID. This is driver packaging, not a replacement image for a graph product:

```sh
CPK_IMAGE=ghcr.io/openj92/control-plane-kit-servers/cpk-server@sha256:336f536d72e2bff7e1c9d19e86c795f935176f6a6f5de878504fb2d948f978ab
docker build -f products/cpk_server/Dockerfile.bootstrap \
  --build-arg "CPK_IMAGE=$CPK_IMAGE" -t cpk-root-bootstrap:review .
DRIVER=$(docker image inspect --format '{{.Id}}' cpk-root-bootstrap:review)
umask 077
mkdir root-bootstrap
docker run --rm --network none --mount "type=bind,source=$PWD,target=/source,readonly" \
  "$DRIVER" python /source/products/cpk_server/examples/root_bootstrap_input.py \
  > root-bootstrap/input.json
```

The example embeds the checkout's actual accepted CPK, PostgreSQL and Secrets
descriptor documents. Edit installation/workspace identities, exact workspace
grants, references, loopback port and the external endpoint in that input. Keep
the three accepted image digests. The example endpoint is a placeholder and is
never treated as verified. No credentials are generated by the example or driver.

Provide existing private material files in one private directory. Each file must
be a bounded regular UTF-8 file with no symlinks and no group/other permissions;
use `0400`. The index is also private. It maps exactly the graph's required
references to flat filenames:

```json
{
  "schema": "cpk.root-bootstrap.material.v1",
  "files": {
    "secret://bootstrap/root-a/control": "control-token",
    "secret://bootstrap/root-a/postgres": "postgres-password",
    "secret://bootstrap/root-a/custody": "custody-root-key",
    "secret://bootstrap/root-a/grants": "provider-credentials.json",
    "secret://bootstrap/root-a/client": "provider-client-token"
  }
}
```

The control token must meet the existing client's ASCII/no-whitespace contract.
The custody key and provider credential/grant document must meet the existing
Secrets bootstrap contract. The provider client token must authenticate against
that supplied document, with the workspace and intents needed by later work.
The `provider_bootstrap_credential_ref` is the logical identity pointing at this
client file; it is not an additional initial payload.

Private GHCR images need explicitly configured pull authority or an already
verified cache. For root pulls, optionally add an `image_pull_credentials` object
to the input mapping registry to a secret reference, and include that reference
in the material index. Its file uses the existing OCI credential JSON format
(`username`/`password`, or `identitytoken`). This authority is separate from
optional public workspace `image_pull_authorities` registrations. The driver
does not copy a host Docker credential file or credential helper.

```sh
sh bootstrap.sh plan "$DRIVER" root-bootstrap/input.json > root-bootstrap/plan.json
# Review the full plan and copy its digest before authorizing acquisition.
sh bootstrap.sh apply "$DRIVER" root-bootstrap/plan.json REVIEWED_PLAN_DIGEST \
  /absolute/private/material/index.json /absolute/private/root-bootstrap-state
sh bootstrap.sh inspect "$DRIVER" /absolute/private/root-bootstrap-state
```

Apply refuses projection/driver drift and unsafe material before acquisition.
It checks exact image digests, derives numeric recipient UIDs from image metadata,
and verifies `0400` delivery into read-only mounts. The driver image uses UID0 for
the existing SDK archive helper. Public setup instead uses the inspected CPK UID,
shares the exact CPK container's network namespace, and receives no Docker socket.

The private receipt records intent before nontransactional Docker or public-setup
stages and observations afterward. Any previous receipt stops apply; it is not
an idempotent repair command. Pending work, conflicting resources, permission
failures or uncertain command outcomes require investigation. No adoption,
automatic rollback, retained-volume reset, rekey or blind retry is provided.
Retained PostgreSQL/Secrets data and protected file volumes survive HOLD. Keep
the receipt and original reviewed plan; do not remove them to force redispatch.
Inspect checks recorded IDs/ownership/running state on completed acquisition;
its prior authenticated readiness observation is explicitly historical.

Public initialization creates the workspace, registers its provider and selected
secret references, admits the local Docker runtime and delivery, imports the
three descriptors, and admits any explicitly supplied pull/ingress authorities.
It uses authenticated context, never payload `actor_scopes`. Returned provider
registration IDs feed reference admissions. Registration is not proof that every
future secret exists or that external provider credentials work. Local public
setup success is reported separately from the unverified external HTTPS endpoint.

## Persistent acceptance root handoff

Bootstrap156 is intended to establish **the named persistent root** used for
ongoing manual/live acceptance. The concrete retained deployment still requires
its own reviewed plan. Record its installation/workspace identities, driver and
plan digest, Docker engine/resource IDs, private receipt location, selected
endpoint and independently verified endpoint evidence in Servers156/CPK1779.
Later manual acceptance uses named workspaces on that root and records public
CPK operation/session/run history. Do not create scattered retained installations.

The owning `./test.sh` fixture is deliberately ephemeral and proves the real
launcher, canonical published products, public setup, numeric delivery,
wrong-credential refusal and no-redispatch behavior. It removes only exact IDs
whose acquisition ownership matches its fixture. It does not establish the
persistent root or earn external endpoint/parent-child tracking acceptance.
The current test refactor remains deferred. Existing #1752 and older resources
are only candidates for a later inventory and explicit retirement plan: this
slice does not delete, migrate, adopt or repoint them.
