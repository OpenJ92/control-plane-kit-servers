## Reused procedure and single cutover

The earlier cpk384 -> corrected web65 replacement used exact daemon/ID/image,
bounded events, graceful stop, retain-by-rename, original name/alias/port reuse,
create-inspect-before-start and authenticated readback. The root bootstrap owner
supplies exact configuration/secret volume subpaths, socket group and create/verify
mechanics. It refuses occupied bootstrap resources and is not an updater.

The issue-specific scripts apply those mechanics only to the one fixed CPK:

1. Frozen input/authority/cache/identity/wiring checks and bounded workspace,
   Desired, exact saved revision and first50 attempts reads occur before the outage. Changed/missing/denied
   revision or changed Current/Desired/generation stops before any mutation.
2. Gracefully signal the exact old CPK, wait30s without SIGKILL, require exit0,
   retain under its explicit backup name. Inspect the borrowed network's active
   members/semantic-alias ownership (at most12). This retrieves normal full Docker
   inspect responses for those active peers internally; only their network/alias
   fields are processed and no peer environment, args or mounts are reported or
   persisted. The future release must name that read scope. Require no active original
   endpoint/alias and no live18163 holder before reusing the original name.
   No assumption is made that a stopped configured endpoint still answers DNS.
   No forced network disconnect is attempted. Docker documents ordinary disconnect
   for running containers: https://docs.docker.com/reference/cli/docker/network/disconnect/ .
3. Create one stopped49ae successor with the same name, declared alias, private
   environment and five file-subpath mounts, existing Docker socket/group and
   port. Private values remain in helper memory/Docker API payload, never command
   arguments, files or reports. Override only the public four-read MCP profile.
4. Record returned ID; inspect actual configured image/process/user/profile,
   ownership, actual and configured mounts, socket/group, private/store wiring,
   intended port and network configuration while stopped. Mismatch/unknown stays
   stopped. Start once only after all comparisons pass.
5. Immediately before start, reobserve the original stopped and semantic alias
   free under North's single-writer window. An original restart leaves the new
   container stopped. Verify actual PID1/UID, bindings/alias owner/single writer
   and unauthenticated readiness, then compare the same four authenticated
   bounded responses. Only those named records
   earn preservation. This does not prove every plan, preparation or history item.

Normal startup calls the selected Operations schema installer. A failed readiness
check can follow committed schema work; no unchanged-DB or rollback guarantee is
made. Unknown effects retain their pending stage/resources; no automatic retry,
repair, downgrade, old-writer restart or cleanup of service/storage follows.

The deterministic create payload is validated before outage. Missing/null image

The maintenance receipt under the fresh run's `maintenance/receipt.json` identifies

Never restart it to clear that expected historical-inspector result. Record the

## Exact invocation shape, after a separate final action approval

```sh
sh scripts/grandparent_cpk_cutover.sh ACTION_JSON APPROVED_ACTION_SHA256 HUMAN_BEARER_FILE PUBLIC_BOOTSTRAP_JSON
```

All paths are absolute reviewed references. The public bootstrap bytes are frozen
to SHA256c451d7cf; the action JSON binds exact source commit, Python/launcher/owner/
daemon-admission file hashes, frozen installer, exact credential source reference
and recipient/reader identity/endpoint before its privileged mount. The bearer
is never hashed. The action must name
its public approval reference and explicitly confirm quiescence, route exposure,
private wiring reuse and verification bearer use. All four must be true before
any Docker-backed helper starts. An unapproved template has false values.
The actual credential custody/reference and final file metadata need North's
confirmation; no credential is requested in chat or read during source work.

The launcher uses only cached installer0d5 and one owned host-network helper
(root for Docker administration, DAC_READ_SEARCH, SETUID/SETGID to drop its read
child to501:20, CHOWN only for newly owned receipts,1CPU/512MiB/128PIDs, readonly
root/tmp32MiB, no published port or logging). Host networking must already be
available; no Docker setting is changed. The real client preserves loopback-only
plaintext and file-owner protections. Its501 child reads the approved file once
through ClientProfile.credential, verifies the human identity with the selected
product verifier, and pins those verified bytes in memory for all four requests.
A valid setup bearer refuses before any request/stop. The private principal
document travels only through an anonymous parent/child pipe; no file copy or
credential argument. Read evidence proves that identity and those named reads,
not every effective scope. Private Docker networking is not a security boundary;
the API/host administration and private delivery require explicit approval.
The existing resource owner removes only the exact labelled helper after its
terminal state is confirmed. Lost/ambiguous helper outcome is preserved and holds;
no automatic force-kill is dispatched while the action may still be running.
Old/new service compute and all borrowed storage/images/network remain retained.
