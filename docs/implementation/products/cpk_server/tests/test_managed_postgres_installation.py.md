# Managed PostgreSQL installation laws

Exercises the public root planner with explicit synthetic managed descriptors:
file/control/data preservation, deterministic graph round trips, installation
password rebinding, authenticated SQL checks, exact receiver target and unique
identity, mandatory verifier families, incompatible process-contract refusal,
private management port, unchanged selected CPK/Secrets and native compatibility.

The runtime seam tests require exact authenticated SQL success, reject a merely
listening server/failed or malformed query, redact uncertain daemon failures
without retry, and retain the native readiness command. They do not simulate
Docker acquisition, initialize databases, qualify images or replace PostgreSQL's
owned signed-health/init/storage tests. Only the normal Docker-backed suite runs
these laws.

Shared material tests reject ambiguous managed trailing-LF input through public
apply before acquisition and resolve both real PostgreSQL/CPK deliveries plus
probe bytes. Native trailing LF remains unchanged. A socketpair feeding the
actual Docker SDK frame reader proves a blocked attached observation is
interrupted, its response closes, the timer/handler are restored and no second
exec occurs. A watchdog bounds a failed test; it does not implement the timeout.
Success/error restoration and active-timer/non-main-thread refusal are also
covered. Remote exec cancellation is deliberately not claimed.
