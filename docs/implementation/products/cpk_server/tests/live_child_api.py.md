[Source](../../../../../products/cpk_server/tests/live_child_api.py) is an effectful public-API acceptance controller in the [unmerged adoption slice](../../../README.md). It sequences parent preparation/deployment, child setup and application admission/deployment, reconnect/history verification and ordered teardown. It calls authenticated public CPK commands; it does not own Operations run/graph semantics or silently recover uncertain mutations.

Product registration is an explicit prerequisite. Parent preparation delegates to `prepare_child_installation`, which imports exact composed product documents before planning. `admit_application` imports Hello, router, gateway and connector documents and checks workspace, active registration and returned reference before ingress/key admissions and application planning. A document already loaded locally is not a registered product. Pending request identity is written before dispatch; mismatched evidence or a pending uncertain phase must not be treated as permission to continue.

Key-command receipts and public key reads have different contracts. Register/activate receipt checks can include the signing-key reference. `read.delegation-keys` is the public/redacted projection: final readback checks purpose, issuer, key ID, workspace, active status, algorithm, registration and public-key fingerprint. It does not require the private-key reference from that public list. Do not extend a fake read response with private fields to satisfy an imagined contract. [test_child_gateway_example.py](../../../../../products/cpk_server/tests/test_child_gateway_example.py) constructs a literal fake of the selected public projection and protects this distinction; verify the owning selected projection on contract changes.

Before executing an approved plan, `apply_reviewed` compares generated fixture operations with public plan operations, including destructive direction. Those fixture comparisons bound this acceptance recipe; Core owns planning and Operations owns approval/dispatch/history. Do not add a parallel generic schema/state machine here. Successful deployment observations bind current graph/projection to the approved plan; reconnect checks durable association and dispatches a fresh bounded gateway probe.
