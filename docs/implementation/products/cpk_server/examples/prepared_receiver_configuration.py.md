# Prepared receiver configuration example

Source: [prepared_receiver_configuration.py](../../../../../products/cpk_server/examples/prepared_receiver_configuration.py).

`two_instances` accepts an immutable caller-selected catalogue document with the
managed Cloudflared required-slot contract, workspace/runtime coordinates,
fresh authoring context, public verifier configuration and two explicit receiver
identities. It validates the expected declaration and distinct identities, then
renders each genuine receiving artifact before ordinary catalogue instantiation.
Both nodes retain the original descriptor/image; no compiled field is stripped,
rebound or repaired.

The example is parameterized because image qualification and public verifier
selection belong to their actual owners. It embeds no image digest, key or token,
and it does not relabel the historical native descriptor as managed. Calling
it returns pure graph data. Caller-owned NamedPublicIngress intent and Operations
activation supply generated secret references/versioned material later; the
example has no direct token deliveries, provider effects or persistence.

The existing two-instance authoring target invokes this exact example with its
explicit never-executed source descriptor fixture and requires the same graph.
That test checks composition/provenance rather than image usability. No full
owning green or live acceptance is claimed by this source checkpoint.
