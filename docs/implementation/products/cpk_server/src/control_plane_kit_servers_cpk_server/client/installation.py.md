[Source](../../../../../../../products/cpk_server/src/control_plane_kit_servers_cpk_server/client/installation.py) composes installation values with the maintained public client. It is part of the [child adoption draft](../../../../../README.md), not the readiness baseline. It owns finite local progress and verified command/read associations; it does not execute Docker, initialize Operations stores, mint secrets or recover an uncertain public mutation.

`child_installation_document` uses the selected Core product/topology codecs and installation composition to produce exact product/graph inputs. `_import_products` derives each expected `ProductReference` from the decoded document, then requires the public import response to match workspace, active registration and that reference. `prepare_child_installation` imports these documents before calling `TopologyClient.plan`. It returns the prepared plan; approval/application and child initialization are separate caller steps.

`_Progress` binds local state to its target and input digest, records pending commands before transport and preserves bounded returned coordinates. A matching local receipt is historical evidence; it must not become fresh deployment truth. Failed preparation or setup raises fixed `ChildInstallationHold` text so provider response bodies, credentials and private input details do not escape.

`initialize_child_workspace` verifies declared setup scopes and target, then uses public workspace/provider/runtime-authority registration/read contracts. Actual credential authentication and authorization remain with the public server/Operations owner; local scope declarations do not confer authority. The controlling scopes and response shapes belong to the selected contracts in [pyproject.toml](../../../../../../../pyproject.toml). Read those owners before adding guessed fields or weakening readback. Exact public commands are not replaced by direct database/provider shortcuts.

[test_child_installation_client.py](../../../../../../../products/cpk_server/tests/test_child_installation_client.py) covers import-before-plan and bounded setup/progress behavior. Public harness integration is in [live_child_api.py](../../../../../../../products/cpk_server/tests/live_child_api.py). Passing fakes do not establish deployed custody, provider success or safe retry of the held live attempt.
